# Tkinter GUI experiment — original UI without Qt

**Branch:** GUI_tkinter (created from work commit 1e6f993).
**Status:** EXPERIMENTAL / NOT VERIFIED ON NATIVE WINDOWS. Not a release or replacement for app.py.

## Objective

Evaluate whether recognizable TittyTatter GUI can run with **stdlib tkinter/ttk instead of PySide6** without touching realtime audio scheduling.

Tk uses Tcl/Tk normally bundled with official Windows Python. The separate environment installs numpy, sounddevice and PyGuitarPro via requirements-tk.txt. It **does not install PySide6/PyQt**.

The original Qt app.py and ./tt run remain unchanged.

## Native Windows commands from WSL

On first use:

    clear
    cd /mnt/f/_PROJECT/TittyTatter
    git fetch origin refs/heads/GUI_tkinter:refs/remotes/origin/GUI_tkinter
    git switch --track origin/GUI_tkinter
    ./tt tk-install
    ./tt tk-smoke

If the branch is already checked out, use git switch GUI_tkinter and git pull --ff-only origin GUI_tkinter instead of the first-time switch.

Then launch:

    clear
    cd /mnt/f/_PROJECT/TittyTatter
    ./tt tk-run

The Qt version remains at ./tt run and uses its own .venv. If tkinter is missing from your Windows Python installation, run py -m tkinter in a Windows terminal to diagnose Tcl/Tk.

## File layout

- tk_app.py — Tk main window, original AudioEngine, Pattern, Training Modes, Picking v2, exports, session and initial Game logic.
- tk_widgets.py — Canvas metronome, existing per-beat pattern semantics with grid/presets/mute, horizontal scroller.
- tk_settings.py — all **eight original settings tabs**, contextual controls for all 14 modes.
- requirements-tk.txt — no Qt requirement.
- test_tk_gui.py — desktop GUI smoke, run with ./tt tk-smoke.
- .venv-tk/ — dedicated Windows Python environment, ignored by Git.
- tittytatter.tk.settings.json — separate Tk preferences, ignored by Git.

**No Tk entrypoint module imports PySide6.** The existing AudioEngine remains the ONLY musical scheduling clock. Tk.after(33, ...) polls/redraws; it does not schedule sound.

### Known limitations

1. This is a functional **port candidate** — not exact pixel parity. Tk native controls differ from Qt.
2. Game parity is incomplete (physical scan-codes, mouse bindings, detailed history/diagnostics, fully equivalent buffering).
3. Picking/Focus overlays are simplified; sweep links and several advanced visual cues need additional work.
4. A few training presentation effects, including ramp-warning animation, are not yet reproduced.
5. Native Windows smoke, interactive audio latency, DPI and mixed subdivision acceptance are **pending**.
6. Audio device selection is not yet restored across restarts; base Tk sound/practice/pattern options are saved separately.
7. Canonical ./tt check remains unchanged (Qt/core). Run ./tt tk-smoke for the Tk GUI without Qt packages.
8. Tk writes only tittytatter.tk.settings.json; JSON sessions interoperate between versions.

## Native acceptance checklist

- Install into an empty .venv-tk and confirm **no Qt packages** are installed; tk-smoke must print "Tkinter GUI smoke OK (no PySide6)".
- Confirm familiar original sections: transport controls, metronome, editable beat cards, 8 tabs, session footer.
- Inspect at 1240x860 and 970x820; scrolling/controls must be usable.
- Exercise TI -> TA -> OFF, triplets, 8-cell subdivisions, long notes, Beat Mute and meter change.
- Start and stop with audible TI/TA. Test BPM, count-in, Ramp, Burst, Gap and other modes.
- Toggle Focus on/off and confirm edited Pattern is preserved.
- Export MIDI/GP5/WAV. Load a JSON session generated by the Qt version.
- Confirm audio device switching and compare subjective latency. **Tk does not change PortAudio's callback clock.**
- Check feature parity and identify remaining gaps before discussing replacement of Qt.
